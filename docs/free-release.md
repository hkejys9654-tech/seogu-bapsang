# 무료 운영용 조회·예약 수정 (2026-10-17)

## 반영 내용

- 일반 직원은 오늘 본인 예약 1건과 본인 제한 정보만 구독한다. 전체 예약 조회는 관리자 화면에서만 수행하고, 관리자 종료·직원 변경·날짜 변경 시 기존 구독을 종료한다.
- 잔여석은 slotCounts의 시간대별 인원을 사용한다. 다섯 시간대 요약과 운영 상태는 처음 열 때와 필요한 새로고침에서만 읽는다. 일반 새로고침에는 60초 간격을 적용한다.
- 예약한 직원은 본인 시간대의 익명 대기 요약만 구독한다. queueEntries에는 순번·인원·대기 여부만 저장하며 직원 이름·번호·예약 ID는 넣지 않는다.
- 예약·취소·호출·입장·재대기를 트랜잭션에서 대기 요약과 함께 갱신한다. 앞선 단체의 실제 인원을 더하고 취소·호출·입장 완료 인원은 제외한다.
- 기존 요약에 완료 표시가 없으면 관리자가 운영 화면을 열 때 현재 예약을 검증하여 한 번 보완한다. 동시에 변경되거나 순번이 불완전하면 완료 처리하지 않고 직원 화면은 ‘대기 인원 확인 중’으로 표시한다.
- 저장 중 시간 변경·중복 클릭, 마감 회차 예약, 반복 노쇼 차감을 차단한다.
- 연결 상태·재시도를 표시하고 확인되지 않은 호출을 초록 입장표로 표시하지 않는다. 캐시에서 서버로 복구될 때 호출 알림 전환도 확인한다.
- 공지 작성 중 입력값과 QR 카메라를 유지한다. 지난 내역은 요청한 직원의 최근 30일 문서만 조회한다.
- 예약 완료와 입장표에 화면을 닫거나 잠그면 알림을 받을 수 없다는 안내를 표시한다.

## 운영 범위

Firebase 요금제 변경, 결제 연결, 새 외부 서버 추가는 없다. 좌석·운영시간과 데모 관리자 인증은 기존 설정을 유지한다. 백그라운드 알림용 미배포 브랜치는 포함하지 않는다.
무료 한도 자체가 없어지는 것은 아니며, 한도·연결 오류는 안내하고 재시도하도록 처리한다. 배포 전부터 열려 있던 관리자·직원 화면은 새로고침해야 모든 변경 경로가 새 대기 요약을 갱신한다.

## 검증

`node --test tests/*.test.cjs`: 90개 통과. Chromium에서 실제 HTML과 모의 Firebase를 이용한 화면 검증 7개 통과(공지 입력·포커스·커서·카메라 유지, 대기 인원 확인 상태와 계산). 실제 직원 예약을 만들거나 시험 호출하지 않았다.
