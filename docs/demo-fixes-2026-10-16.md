# 데모 알림·설치·체크인 수정 (2026-10-16)

## 변경 내용
- 알림 권한 허용과 실제 푸시 등록 성공을 구분한다. VAPID 키가 없으면 `앱 실행 중 알림`으로 표시한다.
- 토큰 발급 및 서버의 `{ok:true}` 응답까지 확인한 경우에만 백그라운드 알림 등록 완료를 표시한다. 실패·차단·시간 초과는 성공으로 표시하지 않는다.
- 알림 클릭 시 내 입장표로 이동한다. 서비스 워커 준비를 무한히 기다리지 않는다.
- 기존 아이콘을 유지하여 192px·512px 파일을 추가했다. 원본은 maskable 안전 영역을 충족하지 않아 manifest에는 `any`로 선언한다.
- 수동 입장과 QR 입장 모두 당일 여부, 현재 예약 상태, 중복 입장 및 노쇼 제한을 검증한다. Firebase는 최신 예약·제한을 트랜잭션으로 읽고 입장 처리한다.
- QR은 발급된 코드 전체가 일치하고 현재 호출 중인 정상 예약이어야 한다. 재대기 후에도 저장된 원래 QR을 사용할 수 있다.
- 관리자 코드와 인증 방식은 변경하지 않았다. 데모의 관리자 수동 입장(호출 여부 우회, 마감후 예약 입장)은 유지한다.

## 검증
`node --test tests/*.test.cjs`: 47개 통과. 실제 앱 함수를 사용한 로컬/Firestore 모의 트랜잭션, 동시 취소·중복 입장, 잘못된 QR, 알림 실패 분기, 서비스 워커 클릭 처리를 검증했다.

JavaScript 구문 및 아이콘 파일 경로·실제 픽셀 크기를 확인했다. 운영 예약 데이터를 생성·수정하지 않았으며 실제 휴대폰 알림 수신과 Firebase 운영 규칙은 검증 범위에 포함하지 않았다.

## 백그라운드 알림의 현재 한계
저장소의 `PUSH_VAPID_KEY`는 비어 있다. 점검 시 `registerPushToken` 서버 URL은 HTTP 404를 반환했다. 따라서 이번 변경으로 앱 종료 후 푸시 수신이 활성화되는 것은 아니다. 현재 데모는 앱을 열어둔 상태에서 호출을 확인하도록 정확하게 안내한다.

추후 Firebase 프로젝트의 Web Push 공개 키를 설정하고 `functions/`의 등록·발송 함수를 배포한 뒤 실제 기기에서 검증해야 한다. 서버 함수와 데이터 접근 규칙은 이번 변경에서 수정·배포하지 않았다.
